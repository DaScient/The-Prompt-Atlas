## 🌌 What is The Prompt Atlas?

**The Prompt Atlas: Kronos Edition** is at once a book, a living web platform, and an open prompt-engineering toolbelt. It is **not a manual for machines — it is a map for minds.** Across **14 chapters in 7 parts**, it bridges economics, ecology, culture, science, psyche, ethics, cosmos, resilience, and play to address one recursive question:

> **How should intelligence — human or artificial — build the future it deserves?**

This repository is the GitHub Pages home of the Atlas (`https://dascient.github.io/The-Prompt-Atlas`, mirrored at `promptatlas.dascient.org`). It contains:

- The full **front-matter** (Foreword, Preface, *The Age of Prompts*),
- A 14-chapter **interactive Chapter Explorer** with case studies, prompts and guiding questions drawn verbatim from the Kronos Edition,
- A **Compendium** page hosting the Epilogue, Post-word, and all six Appendices (Prompt Compendium, Practical Exercises, Case Studies, Glossary of Strange Futures, Reading Atlas, and a year-long Atlas of Daily Prompts),
- Four interactive learning tools and six immersive data visualizations,
- A separately deployed **edge-native API** (Cloudflare Workers + D1 + KV + R2) that exposes the prompt library to developers and AI agents.

## 🚀 Quick Start (GitHub Pages frontend)

The site is **pure static HTML/JS** with CDN-delivered libraries — there is no build step.

```bash
# 1. Clone
git clone https://github.com/DaScient/The-Prompt-Atlas.git
cd The-Prompt-Atlas

# 2. Serve locally (pick one)
python3 -m http.server 8080            # Python 3
npx http-server -p 8080                # Node (no install needed)
php -S localhost:8080                  # PHP

# 3. Open
open http://localhost:8080
```

### GitHub Pages deployment

This repo is published from the default branch via **Settings → Pages → Build from a branch**. Any push to `main` is live within ~60 seconds at:

- **Canonical:** <https://promptatlas.dascient.org>
- **Pages mirror:** <https://dascient.github.io/The-Prompt-Atlas>

For production hardening:

1. Ensure all CDN scripts are loaded over HTTPS (already the case).
2. Enable gzip / brotli at the edge (Pages does this automatically).
3. Set long cache TTLs on `resources/**` and a short TTL on HTML.
4. Front the origin with a CDN (Cloudflare / Fastly / Netlify) for global low-latency.

## ⚡ Edge-Native API (Cloudflare Workers)

In addition to the Pages site, the Atlas exposes a developer-first API.

- **Base URL:** `https://prompt-atlas.aristocles24.workers.dev`
- **Runtime:** Cloudflare Workers
- **Database:** Cloudflare D1 (SQLite)
- **Cache &amp; Counters:** Workers KV
- **Artifact Store:** Cloudflare R2
- **Auth:** API keys via `Authorization: Bearer <key>` *or* `x-api-key`

### Endpoints

| Method | Path | Purpose |
|---|---|---|
| `GET`  | `/health` | Liveness probe |
| `GET`  | `/v1/atlas/categories` | List prompt categories |
| `GET`  | `/v1/atlas/prompts` | Search prompts (`?q=`, `?tags=a,b`, `?limit=`, `?offset=`) |
| `GET`  | `/v1/atlas/prompts/:id` | Get a single prompt |
| `POST` | `/v1/atlas/compose` | **(API key)** Compose a structured prompt from goal / audience / tone / constraints |
| `POST` | `/v1/atlas/lineage/start` | Start a lineage thread |
| `POST` | `/v1/atlas/lineage/:threadId/continue` | Continue a thread |
| `DELETE` | `/v1/mirror/data` | Stateless wipe of caller-scoped data |

#### Compose example

```bash
curl -X POST https://prompt-atlas.aristocles24.workers.dev/v1/atlas/compose \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PROMPT_ATLAS_KEY" \
  -d '{
    "goal": "Design a regenerative urban economy",
    "audience": "City planners and AI advisors",
    "tone": "Visionary, rigorous, hopeful",
    "constraints": ["measurable", "century-horizon", "ecologically symbiotic"]
  }'
```

### Setup &amp; deploy the Worker

```bash
# 1. Tooling
npm install -g wrangler
wrangler login

# 2. Configure
# Edit wrangler.toml: account_id, KV namespace IDs, D1 binding, API keys, env.

# 3. Database
wrangler d1 execute prompt_atlas_db --remote --file schema.sql
wrangler d1 execute prompt_atlas_db --remote --file bootstrap.sql

# 4. Ship it
wrangler deploy
```

Freemium quotas are enforced monthly via Workers KV counters keyed on API key.

## 🛠️ Editing the Site

The site is intentionally hand-tunable. The most common edits:

| Want to change… | Edit… |
|---|---|
| A chapter’s essence, prompts, case study, or guiding questions | `chapters.html` → `chapterData` object (lines ≈ 841 → 1163) |
| The Foreword / Preface / Epilogue / Post-word prose | `compendium.html` → sections `#foreword`, `#preface`, `#age-of-prompts`, `#epilogue`, `#postword` |
| Appendix A prompts / Appendix F daily prompts | `compendium.html` → `#appendix-a`, `#appendix-f` (each month is a `<details>` block) |
| The four interactive tools | `interactive.html` |
| Visualizations &amp; charts | `visualizations.html` (ECharts config + Three.js scene) |
| Nav, hero, footer | `index.html` |
| Cosmic palette &amp; typography | Tailwind config inline in `<head>` of each page (search for `cosmic-` color names) |

All user-supplied strings rendered into the chapter modal are HTML-escaped via `_escapeHtml()` in `chapters.html` — keep that helper in place when extending the modal.

## 📐 Design Philosophy

The Atlas embodies the principles it teaches:

1. **Recursive design** — the platform expects to be edited, forked, and reinterpreted; nothing is finished by design.
2. **Symbiotic aesthetics** — every element pairs human warmth (serif quotation, gold accents) with machine precision (charts, simulations, dark grid).
3. **Accessible intelligence** — complex ideas surfaced through interactive interfaces, not gated behind jargon.
4. **Wonder-driven** — every page is built to leave the visitor *more curious* than when they arrived.
5. **Future-ready** — architected for the edge, ready for quantum-secure transport, designed to outlast trends.
